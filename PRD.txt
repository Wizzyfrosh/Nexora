# Nexora - Master Product Requirements & System Architecture Document

Legacy planning reference. For current implementation requirements, installed versions and feature status, start with README.md, docs/PRD.md and docs/CURRENT_STATE.md. This historical document does not prove that a listed capability has shipped.

## Product Name

Nexora

## Product Type

Multi-Tenant SaaS Business Website Platform

## Vision

Build the easiest platform for small businesses to create and manage professional mini websites without hiring a developer.

The platform should allow business owners to:

* Create a professional business website
* Showcase products and services
* Display prices
* Generate leads
* Receive WhatsApp inquiries
* Customize branding
* Manage subscriptions
* Publish instantly

The platform must prioritize simplicity, speed, scalability, security, and mobile-first experiences.

# Multi-Tenant Architecture

System Type:
Shared Database + Tenant Isolation

Every business is a tenant.

Every business-owned record MUST contain:

* business_id

Examples:

Products
Services
Pages
Analytics
Media
Subscriptions

All backend queries MUST be tenant-scoped.

Never trust frontend filtering.

## Subscription Module

States:

TRIAL
ACTIVE
PAST_DUE
SUSPENDED
EXPIRED

Subscription expiry must be automated.

Expired businesses should display a suspension page instead of being deleted.

---

## Analytics Module

Track:

* Page Views
* Product Views
* Service Views
* WhatsApp Clicks
* Lead Form Submissions

Use Redis queues.

Never write analytics directly to database on every request.

---

## Media Module

Uploads:

* Logos
* Banners
* Gallery Images
* Product Images

Store files in Cloudinary.

Store only URLs in PostgreSQL.
